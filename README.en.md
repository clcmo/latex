# LaTeX Site — Document publishing

A site for compiling and publishing LaTeX documents as PDF and HTML on GitHub Pages, organized by theme.

## How it works

The `.tex` documents live in `src/`, organized by type. On every push to `main`, GitHub Actions compiles each document, generates its HTML version (with rendered math) and publishes:

- an index by theme;
- a viewer page with the PDF and HTML side by side;
- a project presentation.

## Request a document

Anyone can ask to publish, fix or update a document by opening an issue, with no need to touch the code.

1. Open a [new issue](https://github.com/clcmo/latex/issues/new/choose) and choose the **Document (English)** template.
2. Mark the category, the theme and the request type.
3. Give the PDF (name or link) and the source, if they already exist.
4. For a new document, attach the `.tex` file to the issue.
5. A maintainer reviews it, adds the file to `src/`, and the site is updated on the next build.

GitHub usually does not accept `.tex` as an attachment. Send the file compressed as a `.zip` (include images and bibliography, if any), rename it to `.txt`, or, if it is short, paste the content in a code block.

Sending the file does not guarantee publication: the document must compile and goes through review.

## Add a document

For repository maintainers:

1. Create a `.tex` file in `src/articles/`, `src/cv/`, `src/math/` or `src/slides/`.
2. If possible, declare `\title{Document title}` so the title shows up in the index.
3. Run `bash scripts/build.sh` and check the result in `site/`.

The build requires Python 3 and `pdflatex` (TeX Live). `pandoc` is optional: without it, the site only has the PDFs. Documents that use `fontspec` are compiled with `lualatex`; the others with `pdflatex`.

## Themes

The folder in `src/` sets the document **type** (article, resume, slides, notes). The **theme** sets which section of the site it appears in and which accent color it uses.

1. To choose the theme, write at the top of the `.tex`: `% tema: fisica`.
2. Without that line, the default theme comes from the type (see `padrao_por_tipo` in `content/temas.json`).
3. To create or edit a theme, change `content/temas.json` (name, description and `#rrggbb` color).
4. To skip the HTML version of a document, write `% html: off` at the top of the `.tex`.

The HTML version is generated by `pandoc` and is an approximate conversion: documents with many packages (TikZ, colored boxes) may lose formatting. The PDF remains the reference version.

## Structure

```text
.github/
  ISSUE_TEMPLATE/      Issue templates (Portuguese and English)
  workflows/           CI, Pages, READMEs and release
assets/
  css/                 Site styles
  js/                  Site behavior
  python/              Generators for the index, viewers, theme colors and READMEs
content/
  en.md                Source for this README
  pt-br.md             Source for the Portuguese README
  temas.json           Themes (name, description, color) and presentation slides
src/
  articles/            Articles and texts
  cv/                  Resumes
  math/                Math notes
  slides/              Beamer presentations
templates/             Site HTML templates
scripts/build.sh       Local and CI build
```

## Publish on GitHub Pages

Set **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Pushes and pull requests to `main` compile the documents; pushes to `main`
publish the site.

## Update the READMEs

Edit `content/pt-br.md` and `content/en.md`. The build generates `README.md` and
`README.en.md` from those files.
